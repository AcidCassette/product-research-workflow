# Writing Rules · 报告写作硬规则

这份文档是 Phase 3（成文）阶段的写作约束。

这些规则是**硬规则**——不是"最好这样"，是"必须这样"。每一条都有明确的背后原因。

---

## 规则一 · 前置结论

**每节的前三行必须是结论，后面才是支撑。**

### 为什么

读者的注意力衰减很快。如果前三行是铺垫，大部分读者在读到结论之前就跳走了。

### 违反示例

```
§ 3.1 用户分层

两家产品都有分层订阅的定价结构。ElevenLabs 有 Starter / Creator / Pro 三档，Noiz 有 Free / Lite / Pro / Ultra 四档。从价格数字上看差别不大，但从分层逻辑上看有本质差异...（在 500 字之后才说到结论）
```

### 符合示例

```
§ 3.1 用户分层 · 身份模型 vs 计量模型

**核心差异**：ElevenLabs 按"用户身份"分层（hobbyist / creator / pro），Noiz 按"积分额度"分层。

**影响**：身份分层在定价沟通上有更清晰的锚点——价格匹配身份预期、升级理由非用量驱动、用户自我分类更自然。

[后面展开证据]
```

## 规则二 · 结构化语言

**不要堆完整长句。用 bullet、短语、数据。**

### 为什么

Boss 明确反馈过："尽量用结构化的语言，并且尽量说重点，不用非组成完整的一句话，这样信息获取效率会高一些。"

信息密度需要结构化语法来承载。完整长句的语法冗余（主谓宾、连接词、过渡语）会稀释信息。

### 违反示例

> "在我们对 ElevenLabs 进行深度体验后发现，其 Voice Design 功能在用户输入 prompt 时，会默认填充一段示范 prompt，这段 prompt 包含了六个维度的描述信息，包括年龄、性别、音色质感、情感色彩、语速和音质要求，让用户在初次使用时就能知道该如何写一个有效的 prompt。"

### 符合示例

> **ElevenLabs · Voice Design 的 Prompt 引导**
>
> - 默认填充示范 prompt（含 6 维度）
>   - 年龄 · 性别 · 音色质感 · 情感色彩 · 语速 · 音质
> - 下方有快捷标签（Movie Trailer / British CEO / Angry Pirate）
> - 右上角有 Best Practices 链接

信息量一样，占位只有 1/3。

## 规则三 · 证据必须有来源

**每个结论必须对应截图、数据、或引用三选一。**

### 为什么

你今天下午和 Claude 讨论过这件事：判断的价值不来自措辞，来自证据。"非常聪明的设计"没有证据就不是判断，只是修饰。

没有证据的句子让读者必须**相信你的判断力**。有证据的句子让读者**自己做判断**。

后者更可靠、更尊重读者、更禁得起质疑。

### 三种证据的使用场景

| 证据类型 | 适用场景 | 例子 |
|---------|---------|------|
| 截图 | UI / 交互 / 视觉差异 | 定价页对比 / 模型选择界面 |
| 数据 | 流量 / 规模 / 价格 | Similarweb 月访问 / 订阅价格 |
| 引用 | 公开声明 / 文档原文 | 官方 pricing 页面 / 文档原句 |

### 没有证据时怎么办？

**两种处理方式，不能含糊**：

1. **删除**——如果这个判断不重要，删掉
2. **标注**——如果这个判断很重要但暂无证据，标注【个人观察】或【个人推测】

**禁止**：既没有证据、也没有标注，但作为事实陈述出来。

## 规则四 · 交互差异配双图

**涉及产品形态 / 交互逻辑差异时，给两边的截图并排。**

### 为什么

Boss 明确要求。一边截图无法呈现"差异"——读者需要同时看到 A 和 B 才能理解 A vs B 的差别。

### 执行要求

- 截图要**同一位置、同一场景**的对应画面
- 图的**尺寸要一致**（避免视觉权重失衡）
- 必须有 **figcaption** 说明"这是 X 和 Y 在 Z 场景的对比"

### 违反示例

```
ElevenLabs 的定价页是这样的：
[截图]

Noiz 的定价页有所不同，它采用了不同的分层方式。
```

### 符合示例

```
<figure class="dual">
  [ElevenLabs 定价页截图]  [Noiz 定价页截图]
  <figcaption>双方定价页对比 · 身份分层 vs 积分分层</figcaption>
</figure>
```

## 规则五 · 可借鉴点必须具体到动作

**不能写"建议借鉴 X"，要写"建议 Noiz 在 Y 场景下做 Z"。**

### 为什么

Boss 的原话是："核心可以借鉴的点"。借鉴点如果停留在概念层（"借鉴他们的资产哲学"），读者拿到手之后仍然不知道要做什么。

可借鉴点应该是**可执行的建议**——具体到场景、具体到动作、具体到能转为 backlog。

### 违反示例

- ❌ 建议 Noiz 借鉴 ElevenLabs 的 Voice Design 体验
- ❌ 建议 Noiz 优化历史记录功能
- ❌ 建议 Noiz 改进 Prompt 引导

### 符合示例

- ✅ **建议 Noiz 在"音色设计"模块的文字描述框中，默认填充一段包含 6 维度的示范 prompt**（参考 ElevenLabs Voice Design）
- ✅ **建议 Noiz 在 TTS History 面板中增加参数快照字段**（model version / 语速 / 滤镜 / Casualize 状态 / 智能情绪状态），并在每条历史下方增加 "Restore settings" 按钮
- ✅ **建议 Noiz 在音效设计模块新增一个"素材库"tab**，内置分类（自然 / 城市 / 电影 / 动物 / 科技 / 恐怖），作为"描述生成"的替代路径

### 如何验证你的"可借鉴点"够具体

问自己一个问题：

> **一个从未参与过这个调研的开发者或设计师，看到你的建议，能不能直接开始动手？**

如果不能，就是太模糊，回去改。

## 规则六 · 禁止无证据的形容词

**删除所有主观性修饰词——"非常聪明"、"明显优于"、"相当深的洞察"。**

### 为什么

这些词是**自我评价**，不是**客观判断**。它们向读者传达的是"作者觉得很好"，而不是"事实如此"。

而且这些词是 Claude 在写作时最容易加入的"套话"。它们让报告看起来更"有温度"，但实际上稀释了信息密度，并让判断看起来不够审慎。

### 违反示例

- ❌ "这是一个非常聪明的设计"
- ❌ "明显优于竞品"
- ❌ "相当深的洞察"
- ❌ "令人印象深刻的功能"
- ❌ "巧妙地解决了"
- ❌ "完美地实现了"

### 处理方式

**要么**：把评价转成客观描述
- "非常聪明的设计" → "该设计将绝对评价转为相对选择"

**要么**：把评价转成可验证的指标
- "明显优于竞品" → "在 X 指标上比竞品高 20%"

**要么**：直接删掉
- "令人印象深刻的功能" → [删除，只留功能描述]

### 允许的形容词

事实性描述性的形容词可以保留，例如：
- ✅ "完整的" · "局部的"
- ✅ "多轨的" · "单轨的"
- ✅ "可复现的" · "不可复现的"
- ✅ "同步的" · "异步的"

## 规则七 · 区分事实与判断

**所有判断必须明确标注来源。**

### 三种标注

- **事实**（无需标注）——亲眼看到 + 有截图证明
- **【个人观察】**——你的推理、类比、感受，不需要外部验证但要明确标注
- **【个人推测 · 未经核实】**——涉及外部事实的猜测，标注后最好追加 web_search 验证

### 违反示例

> "Noiz 的情绪标签系统之所以出现中英文断裂，是因为它使用了海外模型底座+国内 UI 皮肤的架构。"

这句话把一个**推测**当成了**事实**陈述。

### 符合示例

> Noiz 的情绪标签在 UI 层是中文 emoji，插入文本后变成英文标签 `[Sadness]`。
>
> > **【个人推测·未经核实】** 这种断裂可能源于"海外模型底座+国内 UI 皮肤"的架构选择。此推测未经技术栈确认。

## 规则八 · 附件里才放"过程"

**主报告只给结论 + 证据。思考过程、探索路径、方法论反思一律进附件。**

### 为什么

报告不是思考日记。读者要的是"你得出了什么"，不是"你怎么想到的"。思考过程对**作者**有价值（用于复盘、沉淀、下次做得更好），但对**读者**没价值（他只想知道结论）。

### 哪些内容进主报告

- 核心结论
- 支撑论点
- 关键证据
- 可借鉴点
- 可执行建议

### 哪些内容进附件（或完全不放）

- 探索顺序 / 时间线
- 你用了什么方法论
- 过程中的"啊哈"时刻
- 对自己思考方式的反思
- 自留区的个人感悟

## 规则九 · 优先级要显化

**如果有多条建议，必须标注 P0 / P1 / P2，不能平铺。**

### 为什么

建议如果平铺列出，读者无从判断"先做什么"。而 boss 拿到报告后，最需要的信息恰恰是**优先级**——他要把这些建议转化为团队的 backlog。

### 违反示例

> 建议：
> - 升级 History 存储机制
> - 引入 prompt 引导
> - 添加音效素材库
> - 增加多轨合成能力
> - 重新设计情绪标签系统

### 符合示例

> **P0 · 必做**（投入小、价值高）：
> - 升级 History 存储机制（加入参数快照 + Restore settings）
> - 引入 prompt 引导（Voice Design 模块加示范 prompt）
>
> **P1 · 重要但不紧急**：
> - 添加音效素材库
>
> **P2 · 长期方向**：
> - 多轨合成能力
> - 情绪标签系统重设计

## 规则十 · 每章首行必须可扫读

**读者可能只看每章第一行。这一行必须能独立传达核心信息。**

### 为什么

这是读者"扫读报告"的默认行为——他快速滑过，只看每节开头。如果每节开头是铺垫，他读完整个报告只获得了一堆铺垫。

### 执行方式

- 每节第一行直接给结论
- 用 `**加粗**` 强调核心词
- 避免用"首先 / 然后 / 另外"这种过渡词开头

### 违反示例

> ### § 3.2 决策支持
>
> 首先我们来看两家产品在决策支持方面的差异...

### 符合示例

> ### § 3.2 决策支持 · ElevenLabs 在 4 个场景主动引导，Noiz 未覆盖
>
> **核心差异**：ElevenLabs 在模型选择、素材获取、Prompt 引导、产品外学习 4 个场景都提供了决策支持工具；Noiz 当前版本这 4 个场景都未覆盖。

## 十条规则的元规则

这十条规则本质上在做同一件事：**尊重读者的时间**。

每一条的背后都是：
- 前置结论 → 不浪费读者前 60 秒
- 结构化 → 不用冗余语法稀释信息
- 证据 → 不让读者盲信你的判断力
- 双图 → 不让读者靠想象补全差异
- 具体建议 → 不让读者猜你到底想让他做什么
- 禁止形容词 → 不用情感话术代替事实
- 区分事实判断 → 不让读者不清楚哪些能信
- 过程进附件 → 不用思考日记占用注意力
- 优先级显化 → 不让读者自己猜该先做什么
- 首行可扫读 → 支持读者的最低阅读模式

**如果你记不住十条，就记一条：永远问"读者能不能用最小代价获取最大信息"。**
