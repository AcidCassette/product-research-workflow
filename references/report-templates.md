# Report Templates · 标准报告模板

这份文档提供不同类型 PM 报告的**结构化模板**。选择模板 → 填入内容 → 按写作规则打磨，而不是每次从零设计结构。

---

## 模板选择指南

| 任务类型 | 推荐模板 | 核心问题 |
|---------|---------|---------|
| 竞品分析 | Template A | 竞品的做法能给我们带来什么机会？ |
| 用户研究 | Template B | 用户真正的需求与当前产品的错位在哪？ |
| 产品迭代规划 | Template C | 下一步应该做什么？优先级如何？ |
| 市场扫描 | Template D | 市场上最重要的变化是什么？ |
| 产品体验（单品深度） | Template E | 这个产品的 good / bad 是什么？ |

---

## Template A · 竞品分析报告

**适用场景**：boss 说"调研一下 XX 竞品，给一份竞品报告，看看我们有什么机会"

**标准结构**：

```markdown
# [我方产品] × [竞品] · 竞品分析

## § 0 · 核心结论（首屏可见）

**一句话总结**：[放在红字 / 高亮位置]

**三大核心差异**：
- 差异 1：...
- 差异 2：...
- 差异 3：...

**核心可借鉴方向**：
- P0 · [具体到动作]
- P0 · [具体到动作]
- P1 · [具体到动作]

## § 1 · 我方产品体验

### 1.1 核心功能与交互链路
- 功能清单 + 每个功能的一句话描述
- 核心工作流（配流程图）

### 1.2 商业化路径与方式
- 定价策略
- 订阅分层
- 转化路径

### 1.3 Good · 做得好的地方
- ...（配截图）
- ...（配截图）
- ...（配截图）

### 1.4 Bad · 做得差的地方
- ...（配截图 + 具体场景）
- ...（配截图 + 具体场景）
- ...（配截图 + 具体场景）

## § 2 · 竞品体验

### 2.1 定位
一句话说清竞品在市场中的位置。

### 2.2 核心功能与交互链路
（同我方结构）

### 2.3 商业化路径与方式
（同我方结构 · 便于对比）

### 2.4 与我方核心差异 ★
[重点章节 · 每个差异配双图]
- 差异 1：...
- 差异 2：...
- 差异 3：...

### 2.5 核心可借鉴点 ★
[重点章节 · 具体到动作]
- P0 建议 1
- P0 建议 2
- P1 建议 3

### 2.6 其他重要信息
流量数据 / 融资情况 / 团队等（简要）

## § 3 · 附件
- 详细截图
- 补充观察
- 未验证的推测清单
- 自留区（可选：作者的方法论沉淀）
- 今日工作清单
```

**双星节（§2.4 和 §2.5）是 boss 最关心的部分**，必须配双图、必须具体到动作。

## Template B · 用户研究报告

**适用场景**：做了用户访谈 / 问卷 / 行为数据分析，需要输出研究结论

**标准结构**：

```markdown
# [研究主题] · 用户研究报告

## § 0 · 核心结论（首屏）

**一句话总结**：

**关键发现 · Rule of 3**：
- 发现 1（数据支撑）
- 发现 2（数据支撑）
- 发现 3（数据支撑）

**建议行动**：
- 立即做 · P0
- 计划做 · P1

## § 1 · 研究方法

### 1.1 研究问题
SCQA 的 Q：我们要回答什么？

### 1.2 研究方法
- 样本量、招募方式
- 数据收集手段
- 分析方法

### 1.3 样本画像
- 人口统计
- 产品使用画像

## § 2 · 关键发现

### 2.1 发现一：[主题]
- 数据支撑
- 用户原话（引用）
- 行为证据

### 2.2 发现二：[主题]
（同上）

### 2.3 发现三：[主题]
（同上）

## § 3 · 对产品的启示

### 3.1 当前产品的错位
基于发现，当前产品和用户需求的错位在哪？

### 3.2 建议方向（分优先级）
- P0 建议
- P1 建议
```

## Template C · 产品迭代规划报告

**适用场景**：基于现有数据和调研，规划下一个版本 / 季度要做什么

**标准结构**：

```markdown
# [产品] · [时间段]迭代规划

## § 0 · 核心结论（首屏）

**下阶段核心目标**：一句话

**三大重点方向**：
- 方向 1
- 方向 2
- 方向 3

**关键指标预期**：
- 指标 A：X → Y
- 指标 B：X → Y

## § 1 · 现状分析

### 1.1 数据现状
- 核心指标表（北极星指标 + 支撑指标）
- 对比上阶段 / 对比目标

### 1.2 问题识别
- 核心问题 1 · 数据证据
- 核心问题 2 · 数据证据
- 核心问题 3 · 数据证据

## § 2 · 迭代优先级

### 2.1 P0 · 必做项
每项写明：
- 问题：解决什么
- 方案：做什么
- 预期：什么指标变化
- 投入：工期估算

### 2.2 P1 · 重要项
（同上）

### 2.3 P2 · 储备项
（简要）

## § 3 · 衡量指标
- 北极星指标
- 支撑指标
- 警戒指标（防止副作用）

## § 4 · 风险与依赖
- 已知风险
- 外部依赖

## § 5 · 附件
- 详细方案
- 历史数据
- 未采纳方案的原因
```

## 所有模板的共同特征

注意到没有？所有模板都遵循同一个骨架：

1. **§ 0 · 核心结论（首屏可见）** —— SCQA 的 A 放在最前面
2. **§ 1 - § N · 主体内容** —— 按 MECE 分类的支撑论点
3. **附件** —— 证据、过程、自留内容

这就是金字塔原理在不同报告类型上的**同一种应用**——顶层一句话、中层 3-5 个论点、底层证据。

模板的差异只在于**中层论点的组织维度**：
- 竞品分析 → 按主体分（我方 / 竞品）+ 按维度分（功能 / 体验 / 商业化）
- 用户研究 → 按发现分
- 产品规划 → 按优先级分
- 市场扫描 → 按信息类型分
- 产品体验 → 按模块分

**选模板 = 选中层论点的组织维度**。

## 使用模板的注意事项

### 不要硬套

模板是**起点**，不是**终点**。每次实际使用时，根据任务契约中的 D 调整章节。

例如：如果契约里 D3 是"分析商业化可借鉴点"，Template A 中 §2.5 要特别展开，其他章节可以更简。

### 先填契约，再选模板

顺序是：
1. Phase 0 填任务契约
2. 根据契约中 D 的性质选模板
3. 用模板的结构作为 Phase 2.5 大纲的起点
4. 根据 D 调整大纲的详略和章节

**不要**：先选模板然后找素材填。这样会让报告变成"交作业"，失去真正的洞察。

### 每份报告都要执行摘要

注意每个模板的 **§ 0 · 核心结论**——这不是可选项，是必需项。

这一节是读者可能唯一会读的部分。如果它不能独立传达核心信息，读者就算读了整份报告也不会获得你真正想传达的东西。

### HTML 样式约定

成文时使用已定型的设计语言：
- 字体：Fraunces（display）+ Noto Sans SC（body）+ JetBrains Mono（code）
- 主色：松石灰绿 `#3a6b5f`
- 警示色：琥珀棕 `#8a6a3a`（用于【个人观察】【个人推测】标注）
- 底色：纸白 `#fbfaf6` + 暖纸 `#f3f0e8`

具体 CSS 可以复用已有的 Noiz V2 报告模板。
